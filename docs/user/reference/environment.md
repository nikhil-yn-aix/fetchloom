# environment

environment variables choose the cache, network limits, credentials and terminal behavior.

```powershell
$env:FETCHLOOM_CACHE = 'D:\fetchloom-cache'
$env:FETCHLOOM_JOBS = '4'
$env:FETCHLOOM_RATE = '2.5M'
```

[CLI options](../commands/global-options.md) set per-run behavior. the [settings file](#settings-file) keeps the [resources level](../guides/speed-and-memory.md), the cache, job, retry, timeout, approval, memory, file-count and archive settings, the allowed origins, the S3 buckets your keys may sign for, the cloud storage buckets, drive folders and azure containers your credentials may go to, the mirrors, mirror-only mode, the folder `push` writes to and the rate cap, for every run; a variable wins over it. [`fetchloom settings`](../commands/settings.md) shows each value and where it came from.

a variable one typo from one of these, such as `FETCHLOM_CACHE`, changes nothing, so every command but `help` and `completions` warns about it, naming the variable it is near and never its value. other unknown names are left alone.

| variable | effect |
|---|---|
| `FETCHLOOM_CACHE` | nonempty cache root override |
| `FETCHLOOM_OFFLINE` | `true` or `1` enables offline mode, as `--offline` does. `false` or `0` turns it off; unset or empty means false. any other value, such as `yes`, fails a named command with `usage`, exit 2, before any request. offline recovery hints name the flag, variable or both, whichever enabled it |
| `FETCHLOOM_RESOURCES` | `lean`, `default` or `max`: one word that trades speed against memory by setting what no variable or settings file key sets. `lean` runs 2 requests at once and 2 to one host, gives download buffers 128 MiB, or the default budget when that is smaller, caps local workers at 2, or 1 on one processor, unless `FETCHLOOM_THREADS` is set, and reads a large project's state before listing its data folder, not beside it. `max` runs 32 requests at once and 16 to one host. unset or empty means `default`, which keeps the defaults on this page. no level changes `FETCHLOOM_MOST_FILES`, the archive limits or any other setting. any other value fails with `usage`, exit 2. see [resources](../guides/speed-and-memory.md) |
| `FETCHLOOM_JOBS` | integer from 1 to 256; how many requests run at once. unset or empty means 8. `FETCHLOOM_HOST_JOBS` caps those to one host. requests waiting for a retry, host quota or source spacing release both slots and retake them before sending |
| `FETCHLOOM_RETRIES` | integer from 0 to 20; how many more times a request is tried after it fails and makes no progress. unset or empty means 4. each wait is a random part of a limit that doubles from 1 s up to 1 min, so 10 waits about 3 minutes in all and 20 about 8: raise it on a network that drops for minutes at a time. with no network at all, a run first waits for it without spending tries, up to 5 minutes at a terminal and 30 s where nobody can answer, as in a script or CI; 0 waits for nothing. a source that asks for its requests to start apart, as arXiv does, stops after four answers in a row that it is busy, whatever this allows. a try that moves the download on earns the count back, up to 50 tries in all |
| `FETCHLOOM_HOST_JOBS` | integer from 1 to 256; how many requests may go to one host at once, the streams of a split download included, counting a redirected request by the host it was sent to first. unset or empty means 4. raise it for a host that serves many connections well, such as your own mirror; lower it for one that limits each client. arXiv's hosts take one request at a time together, whatever it says, as [arXiv asks](../sources/arxiv.md#arxivs-terms) |
| `FETCHLOOM_TIMEOUT` | a time from 1 s to 1 h, as whole seconds or with `s`, `min` or `h`, as `30s`, `2min` or `1.5min`; a decimal must come to whole seconds, so `1.5s` is refused. how long a server may send nothing in a response body, or less than 1 KiB, before the try fails and is retried. unset or empty means 30. time held back on this machine by the rate cap, the writer or a question does not count. connecting may take 45 s, or this long when it is longer, and the answer must begin within this once the connection is open |
| `FETCHLOOM_ASK_ABOVE` | a size such as `500M` or `20G`, in the size units below; a download bigger than it needs [approval](../concepts/questions-and-interruptions.md#approval). unset or empty means 10 GiB |
| `FETCHLOOM_MEMORY` | a size such as `512M` or `8G`, in the size units below; the memory download buffers aim to stay within. the downloads running at once share it for the data waiting to be hashed, up to 16 MiB each, and each of the at most four archives unpacking at once may decompress in a quarter of it, never less than 256 MiB. unset or empty means a quarter of the memory available, on linux inside the limit of the process's cgroup, from 256 MiB to 4 GiB and never more than half of what is available. windows counts its available physical memory, macos its free, purgeable and cached file pages. where the system does not say, it means 256 MiB. |
| `FETCHLOOM_MOST_FILES` | integer from 1 to 1,000,000,000; the most files one dataset may list, counted before select patterns apply. unset or empty means the memory budget at about 2 KiB a file, so `FETCHLOOM_MEMORY` raises it too: a 4 GiB budget allows 2,097,152. it is never less than 100,000. a listing past it stops with `source.invalid`, exit 10, naming this setting |
| `FETCHLOOM_ARCHIVE_FILES` | integer from 1 to 1,000,000,000,000; the most entries, files and folders, one archive may unpack to. unset or empty means 10,000,000 |
| `FETCHLOOM_ARCHIVE_SIZE` | a size such as `16T`, in the size units below; the most bytes one archive may unpack to. unset or empty means 16 TiB |
| `FETCHLOOM_ARCHIVE_RATIO` | integer from 1 to 1,000,000,000; the most bytes one archive may unpack to for each compressed byte read, counted once 4 MiB are out. unset or empty means 1000, which nearly all zip data stays under while compression bombs pass it. these three guard against archives built to fill a disk, so only this environment and the settings file move them, never `data.toml`. an archive past one stops with `source.invalid`, exit 10, naming it |
| `FETCHLOOM_ALLOWED_ORIGINS` | origins on this machine or its network that a host written in data.toml, data.lock or a list of files may reach, separated by commas, such as `http://lab.local:8080,http://10.0.0.5:9000`: each a scheme, a host and a port when it is not the usual one, without a path. unset or empty allows none. otherwise such a host on a private, loopback or link-local address is refused with `network.refused`, exit 10, before any request, since a cloned project could point it at your network. a link you type or a mirror you name reaches its own origin for that run, and a refusal quotes the value that lets it through, as a `fetchloom settings set allowed_origins` command or this variable, written before the command for that run alone in bash, zsh and fish, or set with `$env:` in powershell; while this variable is set, or `--no-config` or `FETCHLOOM_NO_CONFIG` leaves the settings file unread, it offers the variable alone |
| `FETCHLOOM_S3_BUCKETS` | the private S3 buckets your [AWS keys](credentials.md#aws-keys) may sign requests for, separated by commas: `s3://<bucket>`, or the bare name, for a bucket on AWS, and `s3:https://<host>[:<port>]/<bucket>` for one at another service that speaks S3's API, such as `s3://lab-raw,s3:https://minio.lab.example:9000/scans`. unset or empty signs for none. see [private S3 buckets](../guides/private-cloud-storage.md#private-s3-buckets) |
| `FETCHLOOM_GCS_BUCKETS` | the private cloud storage buckets your [google application default credentials](credentials.md#google-application-default-credentials) may sign in to, separated by commas: `gs://<bucket>`, or the bare name, such as `gs://lab-private,lab-scans`. unset or empty sends them to none. see [private cloud storage buckets](../guides/private-cloud-storage.md#private-cloud-storage-buckets) |
| `FETCHLOOM_AZURE_CONTAINERS` | the private azure containers a [SAS, an account key or a sign-in](credentials.md#azure-credentials) may go to, separated by commas: `azure:<account>/<container>`, or the container's link, `https://<account>.blob.core.windows.net/<container>`, such as `azure:lab/raw,azure:lab/scans`. in the settings file a link may carry the container's own SAS, as the azure portal gives it. unset or empty sends credentials to none. see [private containers](../guides/private-cloud-storage.md#private-containers) |
| `FETCHLOOM_DRIVE_FOLDERS` | the private google drive folders and files your [google application default credentials](credentials.md#google-application-default-credentials) may read, separated by commas: each by its id or by the link drive gives when you share it, such as `https://drive.google.com/drive/folders/1AbC...`. a folder covers the files google's own listing finds inside it. unset or empty sends them to none. see [private files and folders](../guides/private-cloud-storage.md#private-google-drive-files) |
| `FETCHLOOM_KEYRING` | `false` or `0` keeps fetchloom out of the system's credential store, reading and writing nothing there; `auth login` then asks before using the [credential-file fallback](../commands/auth.md#signing-in), and a key saved in the store before goes unused, with a hint. `true`, `1`, unset or empty uses the store where the system has one. any other value fails a named command with `usage`, exit 2 |
| `FETCHLOOM_MIRRORS` | [mirrors](../guides/mirrors.md) asked for pinned files before their sources, in order, separated by commas: folders, `http://` or `https://` addresses, and S3 buckets, such as `/mnt/lab/fetchloom,https://data.lab.example/fetchloom,s3://lab-data/fetchloom`. text starting with `s3:` is a bucket, other text holding `://` an address and anything else a folder, so `C:\lab` is a folder. a relative folder is taken from the working folder, after `-C`, and a folder whose name holds a comma goes in the settings file's list. `--mirror` adds mirrors before these. unset or empty names none. another scheme, `file://` included, or an address holding a login, a query or a fragment fails with `usage`, exit 2 |
| `FETCHLOOM_REUSE` | folders on this machine read for a pinned file the cache lacks, before any mirror or source, separated by commas, such as `/mnt/usb/datasets`: [reusing other caches](../guides/other-tools.md#reusing-other-caches). unset means hugging face's and kagglehub's caches, where they are folders on this machine, found as their tools find them: `HF_HUB_CACHE`, else `HUGGINGFACE_HUB_CACHE`, else `HF_HOME`'s `hub`, else `$XDG_CACHE_HOME/huggingface/hub`, else `~/.cache/huggingface/hub`, and `KAGGLEHUB_CACHE`, else `~/.cache/kagglehub`. empty reads no folder. a relative folder is taken from the working folder. a file comes in only once its bytes hash to its pin, as a clone where the disk makes one, else as a copy; nothing in these folders is ever written, moved, deleted or linked to |
| `FETCHLOOM_DATA_LINKS` | folders a project's data folder may be a link into, separated by commas, such as `/scratch/you`: a person on a cluster keeps code in a small home and links `data` to scratch. the link is followed only when it is the one link on the way to the data folder and the folder it leads to exists and lies in a listed folder, each compared as resolved; any other link stays refused, as one a cloned project brings, and fetchloom never makes the folder a link leads to or a link of its own. empty follows none. a relative folder is taken from the working folder |
| `FETCHLOOM_WEB_ARCHIVES` | `false` or `0` asks no [web archive](../concepts/offline-and-recovery.md#web-archives) for a pinned file whose link and source no longer give it; `true` or `1` asks software heritage, then the wayback machine. unset or empty means true |
| `FETCHLOOM_MIRRORS_ONLY` | `true` or `1` sends requests to the mirrors alone, never to a source, a search site or a key check: [mirror-only mode](../guides/mirrors.md#mirror-only-mode). `false` or `0` turns it off; unset or empty means false. it needs a mirror, from `FETCHLOOM_MIRRORS`, the settings file or `--mirror`; without one every named command fails with `usage`, exit 2. a file no mirror holds fails with `network.refused`, exit 10 |
| `FETCHLOOM_PUSH_TO` | the folder or S3 bucket [`fetchloom push`](../commands/push.md) copies pinned files to when `--to` names none, such as `/mnt/lab/fetchloom` or `s3://lab-data/fetchloom`. a relative folder is taken from the working folder, after `-C`. unset or empty names none, and push then needs `--to`. push writes to folders and S3 buckets, so a web address, such as `https://data.lab.example/fetchloom`, fails with `usage`, exit 2: copy a folder mirror to the web server with a tool such as rclone |
| `FETCHLOOM_CACHE_BUDGET` | a size such as `200G`: how much the files in the cache may hold. a sync whose downloads would take them past it asks first, as for a disk without room: with no one to ask it stops with `unconfirmed`, exit 1, and with `--yes` it goes on with a `cache.over_budget` warning, whose help says what frees room; for `get`, which has no project, that is `fetchloom cache gc --now`. nothing is deleted to keep within it. unset or empty means no budget. it is never read from `data.toml` |
| `FETCHLOOM_SETTINGS` | nonempty path of the [settings file](#settings-file) to read instead of the default one; the file must exist |
| `FETCHLOOM_NO_CONFIG` | `true` or `1` leaves the [settings file](#settings-file) unread for the run, as `--no-config` does, also one that would stop it. `false` or `0` reads it; unset or empty means false. any other value fails with `usage`, exit 2. data.toml, data.lock and keys are read as always |
| `FETCHLOOM_RATE` | one shared response-body byte budget for metadata, downloads and retries, in bytes a second, written as a size in the size units below, such as `500K` or `2.5M`; unset or empty means no cap. the settings file's `rate` keeps it for every run |
| `FETCHLOOM_THREADS` | integer from 1 to 256; caps [local worker groups and async runtime workers](../../dev/architecture/primitives.md#worker-budgets), not total OS threads. unset or empty keeps the defaults; surrounding whitespace is accepted |
| `FETCHLOOM_SPLIT` | `false` or `0` disables splitting; `true` or `1` starts eligible split downloads from the first answer. unset or empty uses the adaptive trigger: under 1 MB/s over 2 s, with at least 16 MiB left. any other value fails a named command with `usage`, exit 2. files must be at least 64 MiB and pass the [range checks](../../dev/architecture/downloads.md#the-1-mbs-handover). a `FETCHLOOM_RATE` cap turns off the adaptive trigger; `true` and a resumed download whose later ranges are kept still split |
| `FETCHLOOM_LOG` | tracing target filter, such as `fetchloom=debug`; overrides the `-vv` default filter; events include uptime timestamps |
| `FETCHLOOM_TRACE` | nonempty path for a chrome trace, including one `download` span per file; relative to the starting directory, before `-C`; the file is created or truncated even with `--dry-run`, so choose a separate output path; open it in [perfetto](../../dev/engineering/profiling.md#timeline) |
| `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` | the proxy for https links, for http links, and for both when the first two are unset, as `http://proxy.example.org:8080`. a proxy that wants a login takes it in its address, as `http://name:password@proxy.example.org:8080`; messages name a proxy without its login. the lowercase names, such as `https_proxy`, work too, and the uppercase name wins when both are set. an empty value means no proxy. a value that is no proxy address, such as `htp:/proxy:80`, stops a command at its first request with `usage`, exit 2, naming the variable, rather than sending the request without the proxy. a proxy that cannot be reached, as one at a closed port or a name that does not resolve, stops the command with `network.unreachable`, exit 20, naming the proxy without its login and the variable that set it; no other try is made, since the proxy will not come back by itself. [company proxies](../troubleshooting/README.md#company-proxies) shows a local relay for a proxy that wants a windows sign-in. a name this machine cannot look up goes to the proxy, which resolves it, unless the name looks like a private network's: one word, or one ending in `.internal`, `.local`, `.localhost`, `.lan`, `.home.arpa`, `.corp`, `.intranet`, `.private`, `.localdomain`, `.test` or `.invalid`; such a server goes only once `allowed_origins` lists its origin, or as the link a person typed |
| `NO_PROXY` | hosts reached without the proxy, separated by commas, as `localhost,lab.example.org,192.168.0.0/16`: a name covers the names below it too, and an address may carry a mask; `*` reaches every host without it. a key for a plain http host on this machine or your network goes only when `NO_PROXY` lists it, since a proxy would read it. `no_proxy` works too |
| `HF_ENDPOINT` | a mirror of huggingface.co, as `https://hf-mirror.com`, that every request for huggingface.co goes to instead, as hugging face's own tools read it. data.lock keeps huggingface.co links, and hugging face's token never goes to the mirror. a value that is no http or https address stops a command with `usage`, exit 2. [hugging face](../sources/hugging-face.md#a-mirror-of-huggingfaceco) has the rest |
| `HF_TOKEN`, `HF_TOKEN_PATH`, `HF_HOME`, `KAGGLE_API_TOKEN`, `KAGGLE_USERNAME`, `KAGGLE_KEY`, `KAGGLE_CONFIG_DIR`, `ZENODO_TOKEN`, `FIGSHARE_TOKEN`, `OSF_TOKEN`, `DRYAD_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`, `GITLAB_TOKEN`, `S2_API_KEY`, `DATAVERSE_API_TOKEN`, `DATAVERSE_URL`, `NETRC` | each source's key, read as the source's own tools read it, and a variable wins over a key `fetchloom auth login` saved. hugging face's token file is found through `HF_TOKEN_PATH`, `HF_HOME` or `XDG_CACHE_HOME`, kaggle's `kaggle.json` through `KAGGLE_CONFIG_DIR` or `XDG_CONFIG_HOME`, and `NETRC` names the netrc file with logins for other sites. | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_PROFILE`, `AWS_DEFAULT_PROFILE`, `AWS_CONFIG_FILE`, `AWS_SHARED_CREDENTIALS_FILE`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `AWS_ENDPOINT_URL`, `AWS_ENDPOINT_URL_S3`, `AWS_IGNORE_CONFIGURED_ENDPOINT_URLS` | keys, profile, region and endpoint for the S3 buckets in `s3_buckets`, as the aws cli reads them |

[terminal output](../../dev/architecture/output.md#terminal-capabilities) owns color precedence, stream detection and unicode fallbacks.

the shared rate limit permits a burst of one second's bytes or 1 MiB, whichever is larger. `2.5M` allows 2,621,440 bytes per second.

`FETCHLOOM_THREADS` does not change `FETCHLOOM_JOBS`, and network writers and hash workers sit outside its cap, as [worker budgets](../../dev/architecture/primitives.md#worker-budgets) explains.

sizes and rates take a decimal fraction with digits on both sides of the point, and the suffixes multiply by powers of 1024, rounding down to whole bytes. a size needs its unit, so a bare number other than 0, whole as 10 or decimal as 2.5, is refused, since 10 meant as 10G would be 10 bytes; a rate reads a bare number as bytes. signs and exponent notation are refused, and numbers may have spaces around them. a rate takes only the uppercase `K`, `M`, `G` and `T`. a size, as for `FETCHLOOM_ASK_ABOVE`, `FETCHLOOM_MEMORY`, `FETCHLOOM_ARCHIVE_SIZE` and `FETCHLOOM_CACHE_BUDGET`, also takes them as fetchloom prints them, in any case and with a space before them or not: `B`, `KiB` to `TiB` for powers of 1024, and `KB` to `TB` for powers of 1000, so `10G`, `10GiB` and `10.0 GiB` are the same, and `10GB` is 10,000,000,000 bytes. a size of 0 is refused, since a size is at least 1 byte.

a variable that turns something on or off, such as `FETCHLOOM_OFFLINE`, takes `true` or `1` for on and `false` or `0` for off, in any case and with spaces around them.

an invalid value fails a named command with kind `usage` and exit 2, even one that downloads nothing, naming the variable, or the key and the settings file, except in `FETCHLOOM_ACCESSIBLE` and `FETCHLOOM_NO_HINTS`, which change only what you see; help, version and completions still run, and so does the welcome unless `FETCHLOOM_THREADS` is the bad one. an invalid log filter falls back to `-vv`'s default. logging you asked for writes stderr in quiet or JSON mode too, and turns off progress bars.

synced-folder detection reads `OneDrive`, `OneDriveConsumer`, `OneDriveCommercial`, dropbox's `info.json` under `APPDATA`, `LOCALAPPDATA` or the home folder, the icloud drive folder on windows, on macos `~/Library/Mobile Documents` and the onedrive and dropbox folders in `~/Library/CloudStorage`, and on linux a google drive mount of type `fuse.drive` in `/proc/self/mounts`, as google colab mounts it. the home folder is `HOME`, else `USERPROFILE`. on linux and other unix systems, `XDG_CACHE_HOME` and `XDG_STATE_HOME` move the cache and the folder for what fetchloom remembers on this machine when they hold an absolute path, as `XDG_CONFIG_HOME` moves the settings file. on windows and macos, the system's proxy settings fill in when `HTTPS_PROXY` or `HTTP_PROXY` is unset or empty.

## settings file

a settings file keeps settings for every run, so a shared machine or a big scratch disk needs no exported variables. fetchloom reads `settings.toml` in its own folder, beside saved credentials:

| system | settings file |
|---|---|
| linux | `$XDG_CONFIG_HOME/fetchloom/settings.toml` when that variable holds an absolute path, else `~/.config/fetchloom/settings.toml` |
| macos | `~/Library/Application Support/fetchloom/settings.toml` |
| windows | `%APPDATA%\fetchloom\settings.toml` |

`FETCHLOOM_SETTINGS` names another file. no file at the default place is fine; a file the variable names must exist, since its name may be a typo, though `fetchloom settings set` makes it, with its folder. `--no-config`, or `FETCHLOOM_NO_CONFIG=1`, leaves the file unread for one run, also a file that would stop it, and `fetchloom settings` then says it was bypassed.

```toml
cache = "/scratch/lab/fetchloom-cache"
jobs = 32
host_jobs = 8
timeout = 120
ask_above = "50G"
memory = "8G"
allowed_origins = ["http://lab.local:8080"]
s3_buckets = ["s3://lab-raw"]
gcs_buckets = ["gs://lab-private"]
azure_containers = ["azure:lab/raw"]
drive_folders = ["https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz012345"]
mirrors = ["/mnt/lab/fetchloom", "https://data.lab.example/fetchloom"]
push_to = "/mnt/lab/fetchloom"
```

the keys are `cache`, `resources`, `jobs`, `host_jobs`, `retries`, `timeout`, `ask_above`, `memory`, `most_files`, `archive_files`, `archive_size`, `archive_ratio`, `allowed_origins`, `s3_buckets`, `gcs_buckets`, `azure_containers`, `drive_folders`, `mirrors`, `mirrors_only`, `reuse`, `data_links`, `web_archives`, `push_to`, `cache_budget` and `rate`. each takes what its `FETCHLOOM_*` variable takes, as a whole number or text in quotes; `allowed_origins`, `s3_buckets`, `gcs_buckets`, `azure_containers`, `drive_folders`, `mirrors`, `reuse` and `data_links` also take a list of text, and `mirrors_only` and `web_archives` take `true` or `false`. a relative `cache`, a relative folder in `mirrors`, `reuse` or `data_links` or a relative `push_to` is taken from the settings file's folder. an unknown key, a value of another type or a file that is not TOML fails every named command with kind `usage` and exit 2, naming the file, and the help ends with `--no-config runs without the settings file`; help, version and completions still run. a key only a variable sets, such as `threads = 4`, is told so, as `threads is set by FETCHLOOM_THREADS, not the settings file`: `FETCHLOOM_THREADS`, `FETCHLOOM_RATE`, `FETCHLOOM_SPLIT`, `FETCHLOOM_ACCESSIBLE` and the other variables below the keys' own have no key. the file is read only when it is a plain file of at most 1 MiB, so a device or a pipe named there fails at once.

`fetchloom settings set <key> <value>` saves one key and `fetchloom settings unset <key>` takes it out, keeping comments and the other keys. a change holds a lock on a file beside the settings file, `.settings.toml.lock` for `settings.toml`, from reading the file to writing it, so two changes at once both stay, and a read-only settings file is refused and left as it is.

each value comes from the first of these that sets it: its variable, the settings file, the [resources level](../guides/speed-and-memory.md), this machine, fetchloom's default. so `FETCHLOOM_JOBS=4 fetchloom sync` changes one run without editing the file. an empty variable sets nothing, so the file's value stands, but for `FETCHLOOM_ALLOWED_ORIGINS`, `FETCHLOOM_S3_BUCKETS`, `FETCHLOOM_GCS_BUCKETS`, `FETCHLOOM_AZURE_CONTAINERS`, `FETCHLOOM_DRIVE_FOLDERS`, `FETCHLOOM_MIRRORS`, `FETCHLOOM_MIRRORS_ONLY`, `FETCHLOOM_REUSE`, `FETCHLOOM_DATA_LINKS` and `FETCHLOOM_PUSH_TO`: an empty one clears what the file names, so one run can turn off an origin, a bucket, a container, a drive folder, a mirror, a reuse folder, a folder data may link into or a push folder the file sets. [`fetchloom settings`](../commands/settings.md) shows each value and where it came from. the other variables on this page have no key in the file.
