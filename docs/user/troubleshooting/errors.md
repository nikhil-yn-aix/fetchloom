# Errors

| message on stderr | fix | see |
|---|---|---|
| `fetchloom: command not found`, or `fetchloom is not recognized` on windows | open a new terminal, since one started before the install lacks its folder on PATH; if that fails, check that `~/.cargo/bin`, or `%USERPROFILE%\.cargo\bin` on windows, holds fetchloom | [install](../start/install.md) |
| `error: there is no command called "init"` | none is needed: run `fetchloom add <link>` in the project folder | [add](../commands/add.md#what-happens) |
| `error: data.toml has an unfinished git merge conflict`, or `data.lock has ...` | run `fetchloom lock`, which merges both files without downloading; a dataset both sides changed waits for `--ours <name>` or `--theirs <name>` | [after a git merge](../guides/merge-conflicts.md#after-a-git-merge) |
| `error: there is no data.toml in this folder or any folder above it inside the git repository at /home/ada/thesis/experiment` | the search for a project stops at the top of the folder's own git repository: run `fetchloom add <link>` to start one there, or name the project above it with `-C`, as in `fetchloom -C .. sync` | [finding the project](../reference/project-folder.md#finding-the-project) |
| `error: add needs <link>, <path> or -i <file>`, or `error: get needs <link>` | pass a dataset link, or a list with `-i`; `fetchloom add --help` shows the forms | [add](../commands/add.md#usage) |
| `error: offline, and 1 file data.lock names is not in the cache` | sync online first, or remove `--offline` and unset `FETCHLOOM_OFFLINE` if it is `1` or `true`; a CI job can restore a cache that holds the files, as [CI](../guides/ci.md) shows | [offline](../concepts/offline-and-recovery.md#offline) |
| `error: 1 file data.lock names is on no mirror, and mirrors_only lets fetchloom ask its mirrors alone` | ask whoever keeps the mirror to add the file, as a fetchloom that may ask sources can with [`fetchloom push`](../commands/push.md); the details say what each mirror answered | [mirror-only mode](../guides/mirrors.md#mirror-only-mode) |
| `error: gave up on huggingface.co after 5 tries` | run the same command once the network is back; it goes on from the bytes kept, where the server allows it, as the line under the error says. on a network that drops for minutes, set `FETCHLOOM_RETRIES=10` | [recovery](../concepts/offline-and-recovery.md#recovery) |
| `error: export.arxiv.org refused one request after another because it is busy, so this run asks it nothing more` | run the same command later. a source that asks for its requests to start apart, as arXiv does, is asked less often after each answer that it is busy, and after four in a row not at all | [arXiv's terms](../sources/arxiv.md#arxivs-terms) |
| `error: 127.0.0.1 sent a reply that is not valid HTTP` | check the link's `http` or `https` and its port; if the link is right, only whoever runs the server can fix it | [URLs and DOIs](../sources/urls-and-dois.md#accepted-references) |
| `Restarting big.bin · the 2.0 MiB an earlier run kept cannot be continued` | nothing: the file downloads again from its first byte, as from a server that sends no parts of a file, such as python's `http.server`, or after the file changed. a stop against such a server says so, as `the server cannot continue from ... so the next run starts over` | [recovery](../concepts/offline-and-recovery.md#recovery) |
| `error: HTTPS_PROXY is "htp:/proxy:80", which is not a proxy address` | set it to an http, https or socks proxy's address, as `http://proxy.example.org:8080`, or unset it on a network without a proxy; fetchloom never connects around a proxy it cannot read | [environment](../reference/environment.md) |
| `error: could not reach the proxy at http://127.0.0.1:3128, which HTTPS_PROXY names: it refused the connection` | fix the variable, start the proxy, or unset the variable on a network that needs no proxy; fetchloom stops at once rather than trying again. `fetchloom help environment` lists the proxy variables | [environment](../reference/environment.md) |
| `error: the proxy at http://proxy.example.org:8080 asked for a login before it would reach huggingface.co` | the proxy answered 407, wanting a login before it carries any request: for a name and password, put them in the proxy's address, as the help says; a proxy that wants your windows sign-in, by NTLM or Kerberos, needs a local relay that signs in for you | [company proxies](README.md#company-proxies) |
| `error: there is no data.lock, so nothing pins the files' bytes yet` | data.toml was committed without data.lock: ask whoever shares the project to commit it, so you get the bytes they pinned; `fetchloom lock` instead pins what the sources serve today. `status` says `data.lock does not exist` for each dataset | [status](../commands/status.md#categories) |
| `error: data.lock names data.lock.d/clean.450ae405bf79.tsv.zst, which is not there` | ask whoever shares the project for the commit that adds data.lock.d, made with `git add data.lock.d`, then pull it. deleting data.lock and running `fetchloom lock` instead pins what the sources serve now and drops every recipe's pin | [big datasets](../reference/data-lock.md#big-datasets) |
| `error: iris/iris.csv is not the file data.lock records` | the source serves other bytes now: someone who has the pinned ones, such as whoever pinned them, runs `fetchloom push --to <folder>` into a folder you can read, and `fetchloom sync --mirror <folder>` takes them. if the new bytes are intended, run the `fetchloom lock --upgrade` the help names, sync and commit the lock. the JSON `fix` is null | [sync](../commands/sync.md#what-happens) |
| `error: downloading huge.bin needs 2.0 GiB, and fetchloom cannot ask you here` | check the size, then pass `--yes` if you want it. at a terminal with `TERM=dumb`, `FETCHLOOM_ACCESSIBLE=1` asks instead | [approval](../concepts/questions-and-interruptions.md#approval) |
| `error: SSL_CERT_FILE names /etc/ssl/corp.pem, which holds no certificates fetchloom can read` | unset it to use the system's certificates, or set it to a file of PEM certificates | [environment](../reference/environment.md) |
| `error: this sync needs at least 170.0 GiB on the disk holding the cache at /home/ada/.cache/fetchloom, which has 150.0 GiB free`, or `error: downloading iris.zip needs at least 7.9 KiB on the disk holding the cache at ...` part way through a file whose server did not say its size | free space there, or set `FETCHLOOM_CACHE` to a folder on a bigger disk. downloads already in the cache are kept. `--yes` goes on anyway, as on a disk that compresses | [approval](../concepts/questions-and-interruptions.md#approval) |
| `error: the cache at /media/usb/fetchloom is on a FAT32 disk, which holds no file of 4 GiB or more, and scans.zip is 5.2 GiB` | set `FETCHLOOM_CACHE` to a folder on a disk formatted as exFAT, NTFS, APFS or ext4. a project on a FAT32 disk gets the same refusal for its data folder: move the project | [limits](../reference/limits.md) |
| `error: iris/iris.csv already exists with other contents` | move the file somewhere safe, or choose another folder with `--dir` | [existing folders](../commands/get.md#existing-folders) |
| `error: data.csv already exists and holds other bytes than the link serves now` | choose another name with `-o`, or add `--force` to replace it | [a file already there](../commands/get.md#a-file-already-there) |
| `error: huggingface.co has no dataset scikit-learn/irsi, or it is private`, or signed in, `error: hf:datasets/scikit-learn/irsi does not exist, or is not public` | use the command the help gives for a public dataset a typo away, or check the name at the page it gives; only for a private dataset does signing in help | [when a download is refused](../guides/sign-in.md#when-a-download-is-refused) |
| `error: data.example.org refused the token saved for it (401); it may have expired`, or `data.example.org sent a web page, such as its sign-in page, where a file was expected, so the cookies saved for it may have expired` | run the `fetchloom auth login` the help names, which saves a current key or session for the site, then the command again. a page you want as the data takes `--web-page`; when the help names another link, the page a redirect led to, ask for that one | [any website](../guides/sign-in.md#any-website) |
| `error: huggingface.co refused the key in HF_TOKEN for hf:datasets/bigcode/the-stack` | set `HF_TOKEN` to a current key from https://huggingface.co/settings/tokens, or unset it to use the key `fetchloom auth login hf` saves. a refused key in the token file gets ``the key may be old or wrong: `fetchloom auth` shows where it comes from and whose it is`` instead | [when a download is refused](../guides/sign-in.md#when-a-download-is-refused) |
| `error: huggingface.co has no public model scikit-learn/iris, but it has a dataset of that name` | use the dataset link the help gives, as `https://huggingface.co/datasets/scikit-learn/iris` | [hugging face](../sources/hugging-face.md#references-and-pins) |
| `error: iris has no file or folder called not-a-file.csv` | use one of the paths the error names | [path](../commands/path.md#what-happens) |
| `error: kaggle:epa/epa-historical-air-quality cannot be fetched through kaggle's api` | open the dataset's page to see how kaggle offers it, or choose another dataset; a later try gets the same answer | [kaggle](../sources/kaggle.md) |

## common mistakes

### add

| symptom | cause | fix |
|---|---|---|
| a pattern matches nothing | it targets a different source path | inspect listed paths and [pattern rules](../reference/data-toml.md#patterns) |
| `--select` matches nothing in a link to a zip | select chooses among the files a link lists, and the zip is one of them; the help says so whenever the link lists an archive | add the link without `--select`, then keep files inside the zip with a [members table](../reference/data-toml.md#files-inside-archives) or leave some out with [`fetchloom drop`](../commands/drop.md) |
| a shell expands a pattern | the glob was not quoted | use `--select "**/*.csv"` |
| adding fails for inline `datasets` | `add` cannot extend an inline table | use `[datasets.name]` tables |
| a large download stops in CI | it needs approval | check the size, then pass `--yes` if approved |
| `the project folder ... is read-only` | you may not write in the project folder | make the folder writable for you, then add again; on unix this is checked before anything downloads |
| `there is no file or folder "./flower.csv"`, `usage`, exit 2 | the path has a typo, or the file is somewhere else | when one name in that folder is a typo away, the help line gives the command with it, as ``did you mean `fetchloom add ./flowers.csv`?``, keeping your other options; only that folder is read, and nothing is searched for. otherwise the help says which folder a relative path is read from, as `check the path: fetchloom reads ./stuff from ~/my-project` |
| `huggingface.co has no dataset scikit-learn/irsi, or it is private`, or signed in, `hf:datasets/scikit-learn/irsi does not exist, or is not public` | a typo in a hugging face or kaggle id, or a private dataset: both sources answer the two alike | when the owner lists a public dataset a typo away, which `add` asks the source once, signed in or not, and never offline, the help gives your command with the name fixed, as ``did you mean `fetchloom add hf:datasets/scikit-learn/iris`?``, or for a link with a query, a fragment or a login, which may hold a secret, the dataset alone, as `did you mean hf:datasets/scikit-learn/iris?`; no sign-in is offered, and the error is `reference.unresolved`, exit 10. otherwise see [when a download is refused](../guides/sign-in.md#when-a-download-is-refused) |

### sync

| symptom | cause | fix |
|---|---|---|
| `error: offline, and 2 files data.lock names are not in the cache`, though a web mirror holds them | offline asks no web mirror, and the help says so, as `offline asks no web mirror, so http://127.0.0.1:8000 was not asked` | go online, or use what needs no network: a cache that holds them in `FETCHLOOM_CACHE`, or a folder mirror that holds them with `--mirror <folder>` |
| `error: flowers was imported from files, and this machine's cache does not hold them` offline, exit 20 with `offline.missing` | no link fetches an [imported](../commands/add.md#files-on-this-machine) file, so going online does not help, and the help offers no download | copy its files from the folder they came from into the dataset's folder by hand, then sync, or sync with `--mirror <folder>` naming a folder [mirror](../guides/mirrors.md) that holds them; JSON's `fix` is null |
| `error: data.lock pins small/small.csv at 13 bytes, but its SHA-256 is that of 12 bytes on this machine`, exit 50 | data.lock was edited by hand or damaged, as [data.lock](../reference/data-lock.md#encoding-and-validation) explains; `status`, `lock --check` and `push` stop the same way | restore data.lock from git, or set that size back by hand. `--force` does not help, and `fetchloom lock --upgrade` pins what the source serves now, which may be other bytes |

### get

| symptom | cause | fix |
|---|---|---|
| offline get cannot resolve a repository | only a link that kept one file, fetched on this machine before, runs offline | run it once without `--offline`, or for several files follow [offline preparation](../concepts/offline-and-recovery.md#offline) |
| a drive folder includes google docs | selected exports cannot be pinned reliably | [exclude the docs](../sources/google-drive.md) or request fixed files |
| `"fashion" is not a link, a DOI or an id` | search words mixed with links, ids or DOIs, which read as several links | quote the words of one search, as in `fetchloom get "fashion mnist"`, or get one dataset at a time |
| `--sha256 checks one file` | several links, or a dataset with several files | pass one link, and keep one file with `--select` |
| `hf:datasets/scikit-learn/iris@main has no file iris.csv` | the link names a file its site lists under another name, often in other case | write the name the help gives in the link |
| `-o writes one file, and <link> has <n> files` | `-o` writes exactly one file | keep one with `--select`, or put them all in a folder with `--dir` |
| `--force replaces only the file -o names, so it cannot go with --dir` | `--force` replaces the one file `-o` writes, and get never replaces the files of a `--dir` folder | leave out `--force` and give `--dir` an empty folder, or write one file with `-o <file> --force` |
| `data.csv already exists, and its bytes are not the ones --sha256 names` | the hash or the file is not the one you meant | check the hash; if it is right, choose another name with `-o`, or add `--force` |

### push

| symptom | cause | fix |
|---|---|---|
| `holds files, but no fetchloom-mirror file says it is a mirror` | `--to` names a folder that is not a mirror, or a network disk that is not mounted | name an empty folder or a mirror's top folder, and mount the disk |
| `..., read back from ..., holds other bytes than were written, so it was not given its name` | the disk lost or changed a write, so the file read back is not what push wrote | check the disk that holds the mirror, then push again |
| `push needs a folder to copy the files into` | neither `--to` nor `push_to` names one, or an empty `FETCHLOOM_PUSH_TO` cleared `push_to` | add `--to <folder>`, or set `push_to` in the settings file; for an empty `FETCHLOOM_PUSH_TO`, which the help names, add `--to <folder>` or unset it |
| `<archive>: not there on <mirror>` | a members table on the pushing machine left those files out, and push never writes an archive whose files it lists | widen the members table, run `fetchloom sync` and `fetchloom status --verify`, then push again |
