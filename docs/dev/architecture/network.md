# network

`net` turns source requests into bounded HTTP work and verified cache objects. `Net` owns clients, request permits, retry policy, address checks and when a request to an S3 bucket is signed or one to a cloud storage bucket carries a google token. metadata uses `Api`; file downloads use `Fetch` and the cache's partial writer, with disk writes and prefix hashing off the async workers. the [code map](codemap.md#net) lists its files, and the partial writer and hash queue it writes through, `src/cache/partial.rs` and `src/cache/partial/hashing.rs`, under [cache](codemap.md#cache).

## invariants and traps

- a pinned cache miss is rechecked while holding the URL claim, including an uncontended claim. otherwise a completed publication between lookup and acquisition can cause a duplicate body request.

- keep byte processing off async workers and queues bounded. a queue size is not a bound on total project memory.
- hold the partial claim until the writer and hash worker stop using its file.
- range support without version proof is insufficient for joining bytes.
- a cookie a host with a saved credential sets stays in that site's own jar, never the run's shared one, so it goes only where the credential may.
- no credential goes over plain http through a proxy, loopback included: the proxy reads the request whole, and only `NO_PROXY` keeps a loopback link off `HTTP_PROXY`.
- masking is explicit. URL and partial records store only URL fingerprints. cache bodies and other metadata are not sanitized output.
- a shared writable cache trusts its writers; address checks do not isolate cache users. address tests cover radix, percent-encoded and Unicode-dot IPv4 hosts, compressed and embedded IPv6 hosts, scoped-literal refusal, and DNS failure categories.

## tests

idle and byte-rate tests use fixed virtual-clock steps and in-memory response chunks. they assert pending or complete operations and exact bytes, not elapsed wall time. real HTTP tests separately cover transport, redirects and range validation.

## how it works

### metadata reuse

ordinary `Api::get` and `Api::get_with` calls reuse successful metadata within one `Net` run and share identical in-flight requests. `get_with` adds its static headers, as the `apollo-require-preflight` openneuro's GraphQL API asks of a query sent by GET, both to the key and to the request that goes out, so a query is reused only for the same link and headers, never for another query or a plain GET of its link. bodies are shared through `Arc`, not copied. the key follows the outgoing URL and headers, including credential values, plus the signing or token scope; credential refresh and access checks happen before reuse. only 2xx answers are retained. each page keeps its next link and total item count. hints through `get_once` and mirror reads bypass the memo; offline and mirror-only rules still apply.

the allowance is one sixteenth of the memory setting, capped at 64 MiB, with at most 4,096 entries. retained bodies and metadata count against it; old ready entries are evicted and oversized listings are not retained. a dead origin download clears discovery before source recovery, and a request invalidated while in flight cannot repopulate the memo. nothing is persisted. the [measurement](../performance/measurements.md#a-per-run-metadata-memo-2026-11-12) records the speed and memory tradeoff.

### request policy

the bounded download queue takes one job from each initial hostname in turn, retaining order within a host and returning results in input order. a grouped slow host cannot fill the waiting task queue before another host is admitted. host grouping uses the initial request destination, not the cache identity or a redirect destination; ports of one hostname share a group.

retry, host-quota and source-spacing sleeps release both the initial host’s slot and the global slot. the partial-file claim stays held. after a pause, a request retakes its slots before checking the current quota and spending a spacing interval, so a newer limit learned while it queued still applies. cancellation and acquisition errors release ownership; a one-try hint carries the same ownership if a limit changes before it sends.

file bodies use pooled HTTP/1.1 connections, so concurrent bodies do not share a TCP connection. metadata keeps protocol negotiation and HTTP/2 multiplexing. each of the two lanes has a client for trusted origins and one for every other request, each made when a request first needs it. every client shares cookies, checked redirects, credential scope, request permits, the byte-rate budget and, on linux, the TLS configuration `roots::tls` builds once a run, so a second client never reads the system's roots again.

|---|---|

| redirects | at most 10 per attempt |
| metadata body | at most 64 MiB |
| transient attempts | 5 including the first, or `FETCHLOOM_RETRIES` (0 to 20) more than the first; a download try that leaves more of the file held than any try before counts them from the first again, up to 50 tries in all. retries to one host print one warning line, then another only after 30 s of retrying, except to a host that takes one request at a time, through `source::most_at_once`, as arXiv's and semantic scholar's do: it retries one request alone, seconds apart, so each retry gets its line. a try is numbered among all of the request's tries, of the most it may get without progress: its retries left, and only while it waits for a rate limit, the waits for it left too, so a try after a broken connection never counts a wait for a limit the host may not set again. a paced host refusing for load caps that at the refusals `Paces::refusals_left` says it has before `Paces::busy`, so its tries are numbered of four. `Retry::telling` passes each wait to the download's bar as `Event::Retrying`, which shows `try 3 of 5 · next in 2 s` instead of a stall. a body that stops short is told as `failure::broke` words it, `the connection to <host> broke partway through the file`, since reqwest calls every such break "error decoding response body"; the log keeps reqwest's words and their causes. a refused connection names the host and port it tried |

| quota wait | reset within 120 s; at most 10 waits per request before consuming attempts. a download waits for the reset itself, its bar saying `waiting for <host>'s rate limit · try 6 of 15 · next in 3 s`, and one line tells a log of the first wait; a metadata request waits in `Paces`, which tells each reset. the message after the last try counts every request, waits included, and says how many waited |
| diversion pages | at most 3, each at most 4 MiB |

408, 425, 429, 500, 502, 503 and 504 are retryable, as are transient connection and timeout failures. a proxy that cannot be reached is not: `send_on` asks `Proxies::carrier` which proxy carries each hop, and a request that failed before its proxy answered, or that `Proxies::watch` finds without an answer after 3 s, has the proxy checked with a plain TCP connection of at most 5 s, once a run. a proxy that refuses it, does not open it or has a name DNS says does not exist ends the request with `network.unreachable`, naming the proxy without its login and the variable that set it; an answered request records the proxy as reached, so it is not checked again. a check whose lookup failed for now decides nothing. a proxy at an address that drops every packet then fails in 8 s, where five tries of the connect timeout took minutes. a host name that DNS says does not exist fails at once with `network.unreachable`: the resolver in `src/net/address.rs` tells that answer apart from a temporary lookup failure, which is still retried. a reply hyper cannot read as HTTP, such as a status line with a control character or a port that speaks another protocol, ends the request at once with `network.status` naming the host, since a server sends the same reply on every try; through a proxy it is retried, since the proxy may be what sent it and a proxy can recover. redirects and range restarts do not consume the transient-attempt budget. exhausted retries report `network.rate_limited` after a 429, `network.status` after a 5xx and `network.unreachable` otherwise; excessive requested waits report `network.rate_limited` while retries remain.

when a split download remains incomplete, a terminal stream failure keeps priority over transient stream failures in either arrival order. interruption still takes priority.

`Rate` is one shared token bucket across clients, metadata, retries and streams. `Paces` reserves host quota and keeps the lowest remaining count heard within a window. a 429, and a 503 with a `Retry-After`, use up a limit of the host for as long as `Retry-After` asks, as `pace::limits` reads them, so every request to that host waits until then, not only the one refused. a response that omits a known policy still spends one of its remembered requests. a host whose source asks its requests to start apart, through `source::spacing`, gets each hop's request no sooner than that after the last: NCBI's hosts a third of a second, since NCBI asks a program without a key for at most three requests a second and its file server states no limit in headers, arXiv's 3 s, and semantic scholar's API 1 s with a key, its documented rate, or 3 s without one. hosts a source limits together are paced and counted under one name, `source::paced_as`, which `Paces` and the per-host slots key by: arXiv's terms limit its API, OAI-PMH and pages together, so export.arxiv.org, oaipmh.arxiv.org and arxiv.org share one pace and, through `source::most_at_once`, one slot, whatever `FETCHLOOM_HOST_JOBS` allows. a paced host that answers 429 or 503 is asked less often: `Paces::answered` pauses its next request by a ceiling that doubles from its spacing with each refusal in a row, up to a minute, of which `pace::paused` waits the first half and a random share of the second, so clients refused together come back apart. a retry waits at least that pause, `Paces::pause`, so its warning states the real wait, and any other answer ends the run of refusals. a refusal counts only for a request sent once the last counted one's pause ended, so requests that were on their way together, as four to NCBI may be, and were refused in one burst, count once. after four in a row, `Paces::busy` fails every later request to the host at once with `network.rate_limited`, so a busy service is not asked again in that run. waits remain cancellable.

metadata pagination reads every `Link` header field. angle-bracketed targets and quoted parameters keep their commas and semicolons; the first `rel` parameter may name several relations. links with an `anchor` are skipped because their context is not the requested page. a `Content-Range: items <first>-<last>/<total>` header gives `Response.total`, the count of a listing sent in parts.

### trust boundaries

a link, dataverse install or bucket endpoint typed on the command line, the url a dataverse key check asks and each web mirror trust their exact origin, scheme, host and port, and nothing else on that host. hosts in data.toml, data.lock or a `get -i` list get no trust of their own, since a cloned project or a downloaded list could point them at this machine's network: they reach a private server only when the `allowed_origins` setting lists its exact origin, which `Net::with_allowed_origins` passes to `Typed` with the others. `send_on` picks each hop's client by `Typed::trusts`: only the clients for trusted origins have a `Resolver` that may keep private addresses, for hosts a trusted origin is on, so another port or scheme of a trusted host reaches public addresses alone. an origin trusted mid-run, as a link resolved after the clients exist, moves that origin's later hops to its client. `Typed::check` refuses a private address literal whose origin is not trusted before any request. untrusted direct DNS results and address literals reject or filter private addresses. `Net::with_allowed_origins` hands `Typed` the setting as `Allowed`, with where a person changes it, so `failure::refused` quotes the whole value that lifts a refusal: an `allowed_origins` line for the settings file, with the origins it lists already, and `FETCHLOOM_ALLOWED_ORIGINS` for one run, or that variable alone while it sets the list, since it wins over the file. when other origins are trusted on the refused host, it names them in a detail line. a refusal no setting lifts, a link without a host or more than 10 redirects, says to open the link in a browser. the trusted clients' resolver notes a name it found on a private address, so `add` can say, with no lookup of its own, that the origin a person typed is private and quote what a later run needs, since typing it trusted it for that run alone. private covers RFC 1918, loopback, link-local, shared `100.64.0.0/10`, `0.0.0.0/8`, `192.0.0.0/24` (oracle cloud's metadata at `192.0.0.192`), documentation, multicast and `240.0.0.0/4`, plus IPv6 loopback, unique-local, link-local, site-local `fec0::/10`, multicast and documentation (`2001:db8::/32` and `3fff::/20`). `198.18.0.0/15` stays public on purpose: clash and mihomo answer every name with a fake address there. IPv4-mapped, IPv4-compatible (`::a.b.c.d`), 6to4 (`2002::/16`) and well-known NAT64 (`64:ff9b::/96`) addresses are judged by the IPv4 address they carry; the local-use NAT64 prefix `64:ff9b:1::/48` lets each network place that address, so every address in it counts as private. `Wire::new` reads the proxy variables through `Proxies::read` before it makes a client, and refuses with `usage` a set value the proxy matcher cannot read, which it would pass over as unset and so send requests around the proxy. behind a proxy, local preflight lookup rejects an untrusted name if any answer is private; an unresolved name is left to the proxy. local preflight cannot bind the destination chosen by the proxy; its administrator owns that egress policy. preflight caches the local verdict for the run, and trusted origins skip it. that lookup happens before the send deadline.

a [mirror](../../user/guides/mirrors.md) a person named in the settings, `FETCHLOOM_MIRRORS` or `--mirror` gets the trust of a typed link: `Context::net_with` passes the origin of each web mirror to `Net::trust`, so a lab server on a private address may be one, while another port or scheme of its host, such as a data.lock link a cloned project points there, may not. a mirror's files are pinned downloads through the same pipeline as a source's, built by `mirror::web::object`, and its marker and trees are `Api` requests with the 64 MiB body limit. [fetch::mirrors](https://github.com/nikhil-yn-aix/fetchloom/blob/main/src/cli/fetch/mirrors.rs) asks for the marker once a run and skips a mirror whose marker request fails, which costs one request and its retries rather than one per file.

in mirror-only mode `Net::with_mirrors_only` holds the web mirrors' addresses, and `Net::may_ask`, called by `send_on` before the client is made and again for every hop before any proxy check or lookup, refuses with `network.refused` a request that is not a mirror's or not below a mirror's address: the same scheme, host and port, and a path inside the mirror's. a request is a mirror's when its `Fetch` says so, as `mirror::web::object` makes them, or when it goes through `Net::mirror_get`, as the marker and trees do; a source's request to a mirror's host, or a redirect off the mirror, is refused all the same. a refused redirect names the origin it led to and the one that sent it, since a mirror and the server it sends fetchloom to may share a host. the commands refuse earlier with their own words: resolving a new entry, `search`, `get`, the key checks of `auth`, and the files no mirror gave, which `fetch::mirrors::sources_allowed` names with what each mirror said.

a request for an S3 bucket the `s3_buckets` setting lists goes without a key first, so a public bucket never sees one. when S3 refuses it with 401 or 403, `send_on` marks the bucket for the run and sends the same hop once more, signed by `src/source/bucket/signing.rs`, counted as a request; later requests for that bucket are signed from the start. `send_on` asks for the signer before the request takes its place in the host's pace, since keys from a `credential_process` or the AWS CLI may need a program run first, and a signer error ends the request as final: a bucket whose keys failed or expired is never asked again without them. a bucket nobody listed is never signed for, whatever data.toml or data.lock names, and keys reach an S3-compatible endpoint only where the person's AWS settings send them. signing replaces the static credentials of that request, signs `host` and every `x-amz-` header but not `range` or the `if-` headers, never follows a redirect, and skips a link that carries a signature or another secret of its own. when S3 refuses a signed request with 400 or 403 and its keys came from a program, `send_on` reads the refusal's body, at most 64 KiB, through `Net::read_back`, which makes the answer again around what it read, so whoever reads it next reads the same, cut at 64 KiB. an error document whose code is `ExpiredToken` or `TokenRefreshRequired`, which `Signer::says_expired` reads, makes `Signer::expired` forget those keys in their lease and the hop go once more with keys the program gives anew, once a request; S3 repeats the expired session in that document, which no message shows. the response carries a `Keyed` extension, which `Response.keyed` and download refusals read to say whether a key went with the request. the authorization and the session token are sensitive header values; the secret only derives the signing key in `sign.rs` and is never sent.

a request for a cloud storage bucket the `gcs_buckets` setting lists goes without a token first, as an S3 one goes without a key. when cloud storage refuses it with 401 or 403, `send_on` marks the bucket for the run, through [net::Google](https://github.com/nikhil-yn-aix/fetchloom/blob/main/src/net/google.rs), and sends the same hop once more with a google access token, counted as a request; later requests for that bucket carry the token from the start. a 401 to a token, as an expired or revoked one gets, makes the lease forget that token and the hop go once more with a new one, once a request. a token goes only to `https://storage.googleapis.com` on port 443, with the first request and never after a redirect, never for a bucket nobody listed and never with a link that carries a secret of its own. `Net::google_token` gets it with one POST of the grant to google's token endpoint, which follows no redirect, carries no stored credential and takes no request permit, since the request waiting for it holds one; it retries as any request does, mirror-only mode refuses it and offline mode never sends it. no request names a quota project, so a requester-pays bucket is never billed. the response carries an `Authorized` extension, which `Response.authorized` and download refusals read to say whether a token went with the request, and whether a 403 to it said `error="insufficient_scope"` in `WWW-Authenticate`; a listing also takes google's message about insufficient scopes. the authorization is a sensitive header value.

`instead` in `src/net/download.rs` turns a 401 or 403 to a hop that carried one into `Sent::refusal`, which names what was refused, whether saved cookies had expired, and the command that saves new ones. it also turns a web page where a file was expected, once a site's credential went with that answer or a hop before it, into the same kind of refusal through `site::sign_in_page`, since a site whose session ended mostly redirects to its sign-in page and answers 200; a page answered at the link itself, give or take a closing `/`, is the data when its own name ends in `.htm`, `.html` or `.xhtml`, or when `Fetch::page`, which `--web-page` and data.toml's `web_page` set, asks for one, while a page the link was redirected to, on another origin or path, is how a sign-in page arrives: it counts only when `Fetch::page` asks for one, the page is on the link's site, by `site::same_site`, its host but for a leading `www.`, its port, over https or the link's scheme, and its link names no sign-in page, by `site::names_a_sign_in`, a part of its path such as `login`, `signin` or `sso`, or a way back in its query such as `next` or `RelayState`. anything else is refused, and `Sent::moved_out` gives the page's own link as the way to ask for it, since `--web-page` on the moved link would be refused again. that flag is the only thing data.toml reaches here: it adds no host, header or credential.

a 401 or 403 that carried nothing reaches `Net::refused` last in `instead`, after the sources' own checks. a host a source claims, through `Account::from_host` or `source::refused_download`, keeps its source's refusal from `failure::refusal`. any other host is offered `auth login` for its host and port, as the key would be saved: a basic challenge through `Error::needs` with a `.netrc` login, which answers on any hop to its host, and anything else through `Error::needs_site`, whose terminal offer is a picker of the ways in, `site::offered` in `src/cli/auth/site.rs`, and only for the origin the request started on, since a site's credential never follows a redirect. where `Net::carries` refuses plain http, the help says a key goes over plain http only to this machine or an `allowed_origins` origin, or, when a proxy carries the hop to one of those, that no key goes through a proxy over plain http and that listing the host in `NO_PROXY` sends the request straight there, and nothing is offered.

shown URLs and account arguments share `mask_query`: it masks userinfo and each query or fragment value whose name is not on a short harmless list (`dl`, `raw`, `download`, `format`, `version`, `versionId`, `generation`, `persistentId`, `rlkey`, `resourcekey`, and the paging numbers `page`, `per_page`, `page_size`, `limit`, `offset` and `size`, but never a cursor, which some apis make a token), keeping the rest of the text as written, including URL control-character normalization and wholly percent-encoded pasted URLs. a value under a name no list knows may grant access, as dataverse's `?key=` does, so what is shown does not lean on knowing every secret. `secret` names the fields project references reject before writing data.toml or data.lock: names ending in token, secret, password, signature, credential or api key, the short names of signed links, logins and sessions, and `key` on a path of dataverse's api; one-off `get` can use them with masked output. since `key` is a secret on some paths only, `depends_on_path` keeps the lock's check of a link with one from vouching for the next link with the same keys.
