# sources

`source` turns a typed reference or pasted link into a listing whose files can be checked and pinned. adapters own source-specific identifiers, versions, listing pages and access errors. they return `Listing` and `Remote` values through the `Api` interface; the shared network layer owns transport, retries and credentials on redirects. the [code map](codemap.md#source) lists its files, the keys they use under [auth](codemap.md#auth), and `src/source/recorded.rs`, which replays recorded answers in adapter tests, under [tests](codemap.md#tests).

## invariants and traps

- credentials come from the context, never a `Remote` field or a serialized lock. dataverse attaches its installation account to both HTTP refusals and restricted-file metadata errors, including the port when it is not 443.
- no static credential targets a storage host; `no_credential_is_kept_for_a_storage_host` checks `auth::credentials`. AWS keys sign only for buckets `s3_buckets` lists, after a refusal, and a SAS goes only to containers `azure_containers` lists, after one, and never reach `Keyed`, messages or logs beyond the key id's last four characters. a program that gives keys runs only for such a bucket, and nothing it prints, stdout or stderr, reaches an error, a log or a file. a google token goes only to buckets `gcs_buckets` lists, after a refusal; `Authorized` and messages name the account and its file, never the token, the key or the login's secrets. a github key goes to api.github.com alone, never to github.com, where release files are, or the storage github sends them on from, which `a_github_key_never_reaches_github_com_or_its_storage` checks; a gitlab key goes to gitlab.com and a dryad key to datadryad.org, and neither follows a download off its host.
- project references reject recognized secret query and fragment keys. masking a URL is explicit through `Shown` or `shown`, not an invariant of `url::Url`.
- a reported MD5 is checked against the bytes a URL served before its mapping to SHA-256 can be reused, and only for that URL. the remembered SHA-256 must agree with any SHA-256 the source states, including when its listing omits the size.
- mutable services cannot guarantee historical listings. the lock's hashes establish byte identity even when a source changes.
- a digest is read as what its source says it is. dandi's `dandi:dandi-etag` is S3's multipart tag, not an MD5, so only its `dandi:sha2-256` is checked. an OpenNeuro file's git-annex key states a SHA-256 for its `SHA256` backends and an MD5 for its `MD5` ones, and a chunk's key or another backend's states none.
- an accession can name reads rather than bytes: ENA's FASTQ, a run's submitted files and its SRA file are different files. a reference lists one kind, so a lock never presents one as a mirror of another.
- default tests use recorded responses or local servers. [ignored live tests](../engineering/ci.md#live-source-checks) check current services separately.
- an import records no path and no link. its files are walked without following a link, opened below the folder one name at a time on unix, and copied into the cache, never hardlinked, since a link would seal the person's file read-only.

## add an adapter

1. declare the adapter module and a `Reference` variant in `source.rs`. implement identifier parsing and display in the adapter, then wire `Reference::parse`, `Display`, pasted links in `link` and the relevant `known_host` cases. keep `Parsed.file` for file-specific links.
2. wire `resolve_direct` and, for a DOI-capable repository, destination routing in `src/source/doi.rs`. return a checked `Listing`, preserve unavailable entries, bound pagination through `source::Pages`, which refuses a page named again, more pages than `most_files` files need and 100 pages in a row that bring no new entry (a store may pause a listing with empty pages), in the one wording every source's error carries; a walk calls `Pages::begin` for each folder, since an empty folder is one page with nothing in it, and pin the source's version when it offers one.
3. update `fetch_plan` only if transfers need a page diversion or expired-link handler. keep credential origins and redirects in `Net`. a source with an account adds an `Account` in `src/auth.rs`: where its key lives, its header and host, its token page and a check request.
4. choose existing [error kinds](https://github.com/nikhil-yn-aix/fetchloom/blob/main/src/error.rs) for invalid references, refused access, unavailable data and malformed answers. return refusals through `source::refused` or `Error::needs`, so the error names `fetchloom auth login` and a person at a terminal is offered to sign in; with a key for the account on this machine already, the CLI's `with_key_here` says how to check it instead. `net::failure::refusal` offers none for a plain http link, which no key goes to. a source that refuses a name that does not exist as it refuses a private one, as hugging face and kaggle do, uses `Error::needs_or_missing` with the page that shows the name, so the offer says to check the name there before it asks; the offer defaults to no. a source that tells a refused key apart, as the hub's `auth-check` does with a 401 for a request it took as nobody's, names the key by its `Origin` as the network found it, through the environment `source::env` reads, and offers no sign-in for a key from a variable. a malformed answer's help is `error::report_answer`, which sends it to fetchloom's issues at `error::ISSUES`, since only a newer fetchloom can read a service that changed; a listing whose content only the dataset's owner can change, such as a name `source::refused_name` refuses or an OSF file kept outside OSF storage, gets help that names the owner. if a new kind is necessary, update its serialized name, exit mapping and [exit-code reference](../../user/reference/exit-codes.md).
5. add recorded responses under [tests/fixtures/sources](https://github.com/nikhil-yn-aix/fetchloom/tree/main/tests/fixtures/sources) and `Recorded` tests for parsing, display, paging, pins, missing files, access failures and malformed replies. cover command or transfer effects in [CLI tests](https://github.com/nikhil-yn-aix/fetchloom/tree/main/tests/cli). a CLI test runs the real binary, so its requests go to the real host until the host is in the match in `test_source` in `src/net/api.rs`: add every host the source's listings and downloads reach, and the test then sets `FETCHLOOM_TEST_SOURCES` to a local `Routes` server, which a debug build asks at `/<host><path>`, as the [repository tests](https://github.com/nikhil-yn-aix/fetchloom/blob/main/tests/cli/repositories.rs) do.
6. add an ignored live test against a small public record, stating the host in its ignore reason. keep it separate from deterministic recorded coverage.
7. if the source has a public search catalog, add its query and candidate mapping in `src/source/search.rs`, recorded ranking/error tests in `src/source/search/tests.rs`, and update the documented catalog order and [CLI search tests](https://github.com/nikhil-yn-aix/fetchloom/blob/main/tests/cli/search.rs). those tests stand a local server in for each catalog through a variable of its own: add the catalog's API host to `test_endpoint` in net/api.rs with a `FETCHLOOM_TEST_<SITE>_API` name, as `FETCHLOOM_TEST_ZENODO_API` stands in for zenodo.org, and list it with the [debug-only hooks](../engineering/building-and-testing.md#debug-only-hooks).
8. add a page under [docs/user/sources](../../user/sources/README.md) with accepted forms, pinning, limits and access rules. link it from that index, the [user guide](../../user/README.md), the book's `docs/SUMMARY.md` and `llms.txt`. name the source and its reference form where every source is listed: the [README](https://github.com/nikhil-yn-aix/fetchloom/blob/main/README.md), the agent skill's `skills/fetchloom/SKILL.md`, the [compatibility](../../user/reference/compatibility.md#sources) table of each source's API and hosts and the [data.lock](../../user/reference/data-lock.md#what-each-source-records) table of reference forms and file links. update [environment settings](../../user/reference/environment.md) for credentials, relevant examples and help text in `src/cli/args.rs` or `src/cli/help.rs`, and the affected help snapshots.

## how it works

### parse before resolving

`Reference::parse` recognizes identifiers and known pasted-link shapes. dataverse link parsing returns explicit errors for invalid version queries, so routing cannot discard the version or fall back to downloading the page. figshare distinguishes type/title/id links from the title/id links still supplied by figshare, then reads the id and version by position rather than guessing from their values. `Parsed.file` keeps an individual file selection embedded in a link. an unrecognized page on a known source host fails instead of being mistaken for a plain downloadable file. figshare uses the same institutional-host classification for article parsing and page refusal; its API and download endpoints remain plain URLs.

a path on this machine is refused before routing, with no request, so a person's file names never reach a search site. `add` imports such a path itself, through `src/cli/import.rs`: no adapter lists the files, and the dataset's ref is `local`, which parses to `Reference::Local` and never resolves. relocking keeps an import's pin as data.lock has it, through an upgrade too, refuses a changed entry before any source is asked, and takes a new import's whole pin as `Given::Locked`, learning only what its archives unpack to. a download job for an import's file, which has an empty link, is the error of files imported elsewhere, decided in `source_link` in `src/cli/sync.rs`, where a mirror can be tried first.

github and gitlab file-page URLs are normalized to raw URLs before ordinary URL resolution. [URL references](../../user/sources/urls-and-dois.md) owns accepted forms and HTML warnings.

DOIs ask the JSON handle API at `doi.org` for their registered URL. that URL's host selects an adapter. unknown hosts and another DOI are refused without fetching a landing page; DOI prefixes do not select a repository.

### catalog search

`Reference::resolve_in` takes a dataset's select patterns. hugging face lists only the folders [glob::folders](https://github.com/nikhil-yn-aix/fetchloom/blob/main/src/glob.rs) finds in them, the literal folder each starts with, none nested and at most eight, when each exists and holds files, and lists the whole tree otherwise. openneuro walks only the folders `Glob::may_reach` lets through, the ones on the way to or inside each pattern's `Glob::scope`, its folder names before the file's up to its first `**`, and keeps the files `Glob::scope_holds`; it walks everything when a pattern starts with `**` or matches none of the files kept. `Listing::within` names what was listed, an empty scope standing for the top folder's own files, which `Resolved` calls the top folder. other sources list everything, and recovery of a dead link resolves without patterns.

`is_search` recognizes alphanumeric input without a colon, excluding bare DOIs. `search` asks the `--source` catalogs, or every one but ENA and dandi, as `Catalog::asked` picks them, together, each a boxed future polled until it answers or the others' grace ends, for up to `--limit` matches each, three by default, and interleaves their rank order: hugging face, kaggle, zenodo, ENA, GEO, dandi, openneuro, then the next result from each. without `--limit`, `keep` holds 12 of them, `MOST`: every catalog's best, then exact names, then the rest in that order, counting the rest in `Search::left_out`. exact title or last-id matches then move to the front, keeping that order. hugging face is requested with `sort=downloads` and descending direction, zenodo with `sort=mostviewed`, dandi with `ordering=-stars`, and kaggle, EBI's search of ENA's studies, NCBI's E-utilities for GEO's series and openneuro's GraphQL `advancedSearch` with their own ordering. zenodo, ENA and GEO get the words as plain lowercase words, so none is read as an operator; openneuro gets them as a GraphQL variable. GEO needs a second request, `esummary`, for the series' accessions and titles. it computes no global score. `Candidate` carries a canonical reference and optional catalog facts. one failing catalog contributes a warning; all failing returns the first error. CLI selection is separate from source resolution.

### keep listing and transfer separate

`Listing.resolved` names the version to resolve again where the source supports one. zenodo accepts a different concrete id only when the answer names the requested concept id; an unrelated record is an invalid listing. each `Remote` carries a relative path, URL and any known size, SHA-256 or MD5. unavailable entries retain their paths and reasons so filters can explicitly leave them out. `Listing.warnings` carries what a person should know about a listing that is not an error, such as the components an OSF project leaves out; `tell_resolved` in cli/sync.rs prints each one as a warning after the `Resolved` line, so it shows without `-vv` and reaches `--json` `warnings`. `Listing.access` records what the source said about who may read the data, which data.lock keeps as advisory `access`: hugging face reads `gated` and `private` from the revision it already asks for, kaggle reads a dataset's `isPrivate` and calls every competition `terms`. an adapter that learns nothing leaves `Access::Unknown`, never `Public`.

listings accept at most `source::most_files()` files per dataset before selection, which `FETCHLOOM_MOST_FILES` sets and which is otherwise sized from the memory budget at `PER_FILE`, 2 KiB a file, never below 100,000; `source::too_many` names the setting; OSF's walk also counts folders. the OSF walk validates paths before descent and escapes rejected names in its errors, as the shared listing check does. pagination is handled in the adapter and each page is parsed once. this cap does not bound total project size or the number of members inside archives.

`fetch_plan` adds download-page handlers for drive and dropbox and expired-storage-link recognition for OSF. stable source URLs stay in the lock; redirected storage URLs and credentials do not become pins. `may_wrap` names the links whose file may arrive as a zip of itself, kaggle competition files: `Remote::expected_size` then checks no listed size, and `cli::fetch::wrapped` renames a file whose bytes are a zip of only that file to `<path>.zip`, so draft and `get` unpack it through the archive path and the lock records it with `unpacks_to`.

### buckets

`bucket::Prefix` holds a store, an optional S3-compatible endpoint origin, a bucket and a key prefix. `s3://` and `gs://` references parse directly; `s3:https://host[:port]/bucket/prefix/` names an endpoint, refused with a login, query or fragment, and `written_origin` gives the endpoint's origin the trust of a typed link. `Prefix::from_link` takes only HTTP and HTTPS links without a query whose path ends in `/` or names the bucket alone, so a single object link stays `Reference::Url`.

S3 listing uses ListObjectsV2 with `encoding-type=url`, so keys with control characters survive the XML. a dotted bucket name goes path-style on `s3.amazonaws.com`, since the wildcard certificate does not cover it, and an endpoint bucket is always path-style on its host. a 301 or 400 that names a region, through `Response.region` (the `x-amz-bucket-region` header) or the error body, moves an AWS listing to that regional endpoint once. `src/source/bucket/xml.rs` reads elements, text, the five named entities and character references; it refuses document types and CDATA, so nothing can expand, and stops at 32 levels of nesting. cloud storage uses the JSON API with `fields` trimmed to name, size, `md5Hash` and generation, and requires a generation before pinning each object URL to it. a missing generation is an invalid listing, not an unversioned download.

an S3 ETag becomes an MD5 only without a `-`, only on AWS and only in a listing that went without a key: a bucket that needs one may encrypt with keys whose ETags are no MD5. every S3 object keeps its listed ETag in `Remote.etag`, which cloud storage leaves empty. a draft that has no pin or stated MD5 for a file takes its hash from the cache's URL record of the link when the record's strong ETag and size are the listing's and the cache holds the bytes, through `draft::unchanged`, so an upgrade downloads only objects the listing shows new or changed. `Response.keyed` says how a listing request went out; a signed listing moves the object links to the region it was signed for, so a later run signs them for it, and a refusal says whether a key went with it and what to set. `Keyed::refusal` words the same for a download.

a draft for a listing whose `Reference::keeps_versions` pins each file link to the `x-amz-version-id` its bytes came with, through `with_version`. `Fetched.version` carries it from a download, a resume, a split and the URL record of a revalidated link, and `Cache::stated` from the record of a stated MD5, so a cache hit keeps it. a later lock finds the pin by the link without the version. `Net::download` fetches an unreadable pinned version from `unversioned`'s link and lets the pinned SHA-256 decide, asking first for the object there now once its bucket refused a version this run, as [network](network.md#resumption-and-revalidation) describes.

in debug builds, `FETCHLOOM_TEST_BUCKETS` sends every request for an `amazonaws.com`, `storage.googleapis.com` or `blob.core.windows.net` host, listings and object bytes alike, to `/<host><path>` on a local server, which [CLI bucket tests](https://github.com/nikhil-yn-aix/fetchloom/blob/main/tests/cli/buckets.rs) serve with `Routes` or `Server`. requests are signed as sent to that server.

### signing private S3 buckets

`Signing` holds the buckets `s3_buckets` lists and what a run learns. `locate` reads the bucket of a request from its host and path: any AWS S3 host over https, and an endpoint only when a listed bucket is there. a link carrying a secret of its own, as a presigned one does, is never located. [network](network.md#trust-boundaries) owns when a located request is signed. `refused` marks a listed bucket after S3 refused it unsigned, learns the region its `x-amz-bucket-region` named, and reads the AWS settings once per endpoint through `auth::aws::find`; `signer` then gives the keys, through `Identity::keys`, and the region: the host's, else S3's, else the identity's, else `us-east-1`. `signer` is async, since a program may run for the keys, and holds the state's lock only to look the identity up. once a refused bucket's settings could not be read, or its program failed, `signer` returns that error for each later request, which is then never sent without a key. `Signer::headers` builds `x-amz-content-sha256`, `x-amz-date`, `x-amz-security-token` and `authorization` with `src/net/sign.rs`.

`auth::aws::find` reads the environment's keys, else the chosen profile's in the order botocore takes them: a profile with `role_arn`, `source_profile`, `web_identity_token_file` or any `sso_` key gets `Program::cli`, `aws configure export-credentials --profile <name> --format process`; then keys in the credentials file; then `credential_process` through `Program::process`; then keys in the config file. an identity is bound to the endpoint `AWS_ENDPOINT_URL_S3`, `AWS_ENDPOINT_URL` or its profile names, AWS when none: it signs only for that endpoint, and an endpoint bucket otherwise takes the one profile whose `endpoint_url` names it. unit tests pass a `Var` and temporary files; the CLI sandbox clears every `AWS_*` and `AZURE_*` variable and points the shared files at nothing. `auth::aws::describe` finds the identity as `find` does, for the endpoint the settings send S3 requests to, and says how its keys come without running anything: written keys by their id's last four characters, or the kind of program. `fetchloom auth` lists it, google's credentials through `Credentials::described`, the file and a service account's email, and azure's through `auth::azure::describe`: the SAS or key `find` keeps to an account, then what other accounts get, the az cli counting only once `azureProfile.json` in `AZURE_CONFIG_DIR` or `~/.azure` lists a subscription, whose user it names. it never reads the az cli's token cache.

`Program::process` splits the setting with `words`, by python's `shlex.split` rules, or the microsoft C runtime's on windows, as botocore's `compat_shell_split` does, and finds a bare program name with `installed`, which searches only the folders PATH names by a full path; a name with a relative folder is refused. `Program::run` hands the program to `src/auth/process.rs`, whose `printed` starts it from its own folder with stdin and stderr closed, reads stdout on a thread up to 64 KiB, and polls the child, ending it at 60 s, at too much output or once `Stop` asks, and whose `Ran::said` words a failure; the az cli's token request runs through the same `printed`; `read` takes version 1 JSON and names what is wrong without repeating any of it, and `instant` reads `Expiration` through `toml`'s RFC 3339 datetime. keys that expired by the run fail it. the [shared lease](https://github.com/nikhil-yn-aix/fetchloom/blob/main/src/auth/lease.rs) keeps the last keys in a tokio mutex, with the time from the request to their `Expiration` as their lifetime, so the first request past their renewal, 5 minutes before the expiry or halfway through shorter keys, runs the program while the others wait; keys without an `Expiration` are kept for the run, and a failure other than a stop is kept for every later request. keys S3 says expired, as [network](network.md#trust-boundaries) describes, go through `Identity::forget` to `Lease::forget`, so the next request runs the program again; written keys have no lease and stay.

### a SAS for private azure containers

`net::Azure` holds the containers `azure_containers` lists, each with the SAS its entry's link carries, and what a run learns. `locate` reads the account and container of a request over https on port 443 to `<account>.blob.core.windows.net`; other hosts and ports, and links that carry a secret, are never given a SAS. azure's listing is read in `src/source/bucket/azure.rs`, as another `Store` of `bucket::Prefix`, with the MD5 azure keeps when it keeps one. [network](network.md) says when the SAS goes.

### google credentials for private cloud storage buckets

`net::Google` holds the buckets `gcs_buckets` lists and what a run learns. `locate` reads the bucket of a request to `storage.googleapis.com` over https on port 443: an object by its first path segment, or the JSON API's `storage/v1/b/<bucket>` and `download/storage/v1/b/<bucket>` paths. upload and batch paths, other hosts and ports, and links that carry a secret are never located. [network](network.md#trust-boundaries) owns when a located request carries a token. `refused` marks a listed bucket after cloud storage refused it without one and reads the credentials once a run through `auth::google::find`; `bearer` then gives the token from the same kind of lease as a program's AWS keys, which asks the token endpoint when it holds none or the one it holds is within 5 minutes of expiring, once for every request that waits, and keeps a failed answer other than a stop for the run.

`auth::google::find` reads the file `GOOGLE_APPLICATION_CREDENTIALS` names, else `application_default_credentials.json` in `CLOUDSDK_CONFIG`, `%APPDATA%\gcloud` on windows or `~/.config/gcloud`. a `service_account` key signs an RS256 assertion with `ring`, which rustls already brings, for the `devstorage.read_only` scope; an `authorized_user` login sends its refresh token with its client. other types, such as `external_account` and `impersonated_service_account`, a `token_uri` other than google's three and a named file that cannot be read stop the request, never falling back to another identity. `Credentials::answer` reads the token and its lifetime, or words google's refusal with its `error` and `error_description`, escaped and shortened, never the body. unit tests pass a `Var` and temporary files; the CLI sandbox clears every `GOOGLE_*` and `CLOUDSDK_*` variable, and in debug builds `FETCHLOOM_TEST_GOOGLE_TOKEN`, read once when the network is made, sends token requests to a local stand-in.

### google credentials for private drive items

a drive item's page or download refused without a token, as `folder::read` and `page::divert` say with `auth.required`, goes to `Api::drive_refused`, which `Net` answers through `src/net/google/drive.rs` and which every other `Api` answers with `Private::Unlisted`, so recorded tests keep the public path. `Private::Ready` lets `src/source/drive/private.rs` list the folder with `files.list`, one `'<id>' in parents and trashed = false` query a folder, 1000 items a page, bounded by `most_files` for files and for folders and by `most_files + 1` pages, refusing an `incompleteSearch` answer, a path `name::escapes` refuses or a folder met twice. a file keeps the `https://drive.google.com/uc?id=` link of a shared one, with drive's size, `sha256Checksum` and `md5Checksum`; docs and shortcuts are unavailable entries. `Unsigned` and `Unlisted` keep the page's refusal, worded for credentials or for `drive_folders`. an open link refused this way is a folder or a file as `files.get` says.

`Net::drive_refused` marks the item refused for the run and, when no listed item is it and no listing found it, runs `search` once a run for each listed folder in turn, in the order `drive_folders` names them, until one holds it: the folder's page first, then, refused too, its listing through drive's api. the search asks `drive_refused` again for the listed folder itself, so the method returns a named boxed future. the download side, `Net::drive_download`, sends a `uc` link the network may carry a token for straight to `files.get` with `alt=media`, otherwise tries the shared route first and, once it is refused and `drive_refused` says ready, goes to drive's api, named by google's listing or by one `files.get` for a lone file, since drive's api sends no file name with the bytes.
